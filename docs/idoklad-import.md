# iDoklad historical invoice import

iDoklad documents a **POHODA XML export** at **Nastavení → Aplikace → Export**. Choose the needed month and include **Faktury vydané**. Repeat for each month of history. The download is a ZIP named `idokladImportPohoda`; extract `iDoklad2PohodaExportIssuedInvoice_YYYYMMDD_HHMMSS.xml` and select that XML in the app. Do not mark the invoices exported merely for this local migration, because that changes subsequent iDoklad export selection. The current importer reads one extracted XML file at a time. It does not read the ZIP directly or connect to the iDoklad account.

The preview validates every `dataPackItem` without writing. It shows importable, duplicate, and blocked rows. Commit takes the previewed content hash, rechecks the database, and writes all importable rows in one SQLite transaction. Any blocked row prevents the entire file from committing. Identical invoices in a later export are skipped; a number collision or a changed previously imported invoice is blocked for manual review. The original invoice number stays intact. Imports advance the app's `YYYY-NNNN` counter when relevant so a new invoice cannot reuse an imported number.

This is an intentionally narrow, reviewable POHODA 2.0 subset. A row needs an issued invoice type, original number, issue/due/tax-supply dates, customer snapshot, line descriptions and quantities, explicit `homeCurrency/unitPrice`, `homeCurrency/price` and `homeCurrency/priceVAT`. A summary `homeCurrency/priceSum` is checked against the line amounts when present. Exact decimal line base/VAT values and the decoded source XML are preserved in backup metadata; the UI can export the source for an invoice. The original file byte SHA-256 is also recorded when the UI supplies it. XML is bounded to 5 MiB, 1,000 invoices, 100,000 nodes, and depth 32; DTD/entity declarations and non-POHODA namespaces are rejected.

Foreign currency, advances, credits, discounts, rounding, negative amounts, and unfamiliar detail items are blocked. A line with missing explicit monetary values is blocked, even if a unit price could be multiplied or a tax rate could be guessed. The POHODA transfer is not a reliable record of iDoklad payments, historical seller identity, or historical tax registration. Imported invoices therefore have `archived` status, null seller and regime, and unknown payment state. They are available for historical review and annual reconciliation, but VAT filing remains blocked until the source tax facts are reviewed. This importer never creates payments or a paid date.

The included XML tests are **schema-shaped fixtures**, not a real iDoklad customer export. Real iDoklad files can contain fields outside this subset and will show blockers in preview. A failed preview is a request for a mapping review, not permission to silently discard fields.
